# VidCropper

Локальный видеоредактор: ASP.NET Core .NET 10, HTML/CSS/JS и нативный FFmpeg. Без Node.js и npm для запуска, без внешних сервисов.

## Запуск и порт

В исходном проекте нужен .NET 10 SDK: запустите `Start.cmd`. Браузер откроется после старта сервера. В portable-сборке .NET уже включён.

- `Start.cmd` — порт из `appsettings.json` (по умолчанию **5180**).
- `Start.cmd 5300` — запуск на порту **5300**.
- `Start.cmd 0` — автоматически выбрать свободный порт и открыть правильный адрес.
- Вручную: `dotnet run -- --port 5300 --OpenBrowser=true`.
- Постоянная настройка: `LocalServer:Port` в `appsettings.json`. Также поддерживается переменная окружения `LocalServer__Port`. Аргумент `--port` имеет приоритет.

Сервер слушает только `127.0.0.1`. Если выбранный порт занят, приложение завершится с понятным сообщением, не останавливая чужой процесс. Кнопка **«Завершить»** останавливает сервер и обработку, очищает временную папку. В консоли можно нажать Ctrl+C. Закрытие вкладки освобождает её файлы по возможности, но не завершает сервер.

## FFmpeg и настройки

`ffmpeg.exe` и `ffprobe.exe` ищутся в папке `tools` рядом с приложением, затем в PATH. Явные пути можно задать в `appsettings.json`:

```json
{
  "LocalServer": { "Port": 5180 },
  "Media": {
    "FfmpegPath": "D:\\Tools\\ffmpeg\\bin\\ffmpeg.exe",
    "FfprobePath": "D:\\Tools\\ffmpeg\\bin\\ffprobe.exe",
    "MaxUploadBytes": 10737418240
  }
}
```

Нужна сборка FFmpeg с libx264 и AAC. На текущем компьютере проверена установленная FFmpeg 7.0.2. По умолчанию лимит одного исходника — 10 ГБ. Изменения настроек требуют перезапуска.

## Работа

Перетащите одно видео или выберите его кнопкой. Предпросмотр открывается локально через Blob URL. Одновременно оригинал потоком передаётся **только локальному серверу** во временную папку для ffprobe и экспорта. Никакой копии с перекодированием для предпросмотра нет. Неподдерживаемый браузером кодек показывает ошибку.

Выберите пропорции и рамку. Режим «Свободно» сохраняет рамку и снимает ограничение пропорций. Рамка перемещается мышью или стрелками (Shift — шаг 10 пикселей). Процент считается от кропа; размеры округляются вниз до чётных, минимум 2×2. Предпросмотр показывает композицию, а не качество кодирования или выходной FPS.

Экспорт: MP4, H.264/libx264, CRF 16, preset medium, Lanczos, квадратные пиксели, yuv420p. FPS выбирается в интерфейсе. Звук по умолчанию сохраняется и кодируется в AAC 192 кбит/с, если аудиодорожка есть. Звук проигрывателя независим от экспорта.

Прогресс поступает от FFmpeg через SSE. После проверки готового файла появляется **«Скачать MP4»**, фактические размеры, FPS, длительность и объём. Одновременно выполняется один экспорт. Настройки блокируются на время обработки. Отмена останавливает дерево процесса FFmpeg и удаляет незавершённый файл.

Исходник удаляется при замене видео; предыдущий результат — при следующем экспорте/замене видео. Скачанный файл остаётся в папке загрузок браузера. Рабочие файлы хранятся в `%TEMP%/VidCropper/<идентификатор-запуска>` и удаляются при штатном завершении. При аварийном отключении питания папка может остаться; приложение не удаляет папки других запусков.

## Portable-сборка Windows x64

Из PowerShell выполните `./Publish.ps1`. Скрипт создаёт `artifacts/portable` с .NET runtime, фронтендом и установленными FFmpeg/ffprobe. При необходимости передайте `-FfmpegPath` и `-FfprobePath`. Эта папка запускается через свой `Start.cmd`, без установки .NET, Node или служб. FFmpeg нужен в виде самостоятельных exe; лицензия и README установленной сборки копируются при наличии.

## Проверки

```powershell
dotnet build -c Release -o artifacts/backend-build
node --test tests/geometry.test.mjs tests/backend.test.mjs
```

Node нужен только для тестов, пакеты npm не используются. Интеграционные тесты создают синтетические видео, запускают отдельный сервер на свободном порту и проверяют реальный результат FFmpeg, поворот, звук, нечётный кроп, отмену, валидацию, занятый порт и очистку. Тестовые видео лежат в `artifacts/backend-tests`.

## API

- `GET /api/config` — доступность инструментов и лимит загрузки.
- `PUT /api/media/{guid}?name=...` — поток исходного файла, `application/octet-stream`; ответ содержит метаданные.
- `DELETE /api/media/{guid}` — освобождение исходника (после текущего экспорта, если он используется).
- `POST /api/exports` — `mediaId`, `crop: {x,y,width,height}`, `scale`, `fps`, `audio`, `sourceWidth`, `sourceHeight`.
- `GET /api/exports/{guid}` и `/events` — статус и SSE.
- `POST /api/exports/{guid}/cancel` — отмена; `GET .../download` — скачивание.
- `DELETE /api/exports/{guid}` — отмена при необходимости и удаление результата.
- `POST /api/shutdown` — штатное завершение приложения.

Изменяющие запросы требуют заголовок `X-VidCropper: 1` и при наличии Origin — свой локальный адрес. Входные параметры проверяются сервером; команды запускаются через ArgumentList без shell.
